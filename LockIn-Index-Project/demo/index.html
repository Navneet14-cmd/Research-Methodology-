LII

Lock-In Index

Measuring cloud vendor lock-in from Terraform code · Soni, Pant, Toshif

How locked-in is a cloud application? We turned that question into a number.

The analyzer reads Terraform code, finds every cloud resource it declares, scores each one on four dimensions of lock-in, and averages them into a Lock-In Index from 0 to 100. We ran it on public Terraform code and used the results to answer four research questions.

The pipeline

  1. 1Collect28 public GitHub repos, cloned at fixed commits
  2. 2Find rootsFolders that are deployed directly
  3. 3ExtractEvery resource "type", following local modules
  4. 4Classify21 service categories by pattern rules
  5. 5ScoreLII(r) = 0.35A + 0.25D + 0.25E + 0.15X
  6. 6AnalyseAverages, tests, sensitivity, figures

What if the rubric were different?

The rubric weights are our judgment. Move the sliders to change them, and every score in the dataset is recalculated. If the conclusions still hold, they don't depend on our exact choices. That is RQ4, done by hand.

Weights

Weights are normalised to add up to 1. "Random rubric" also shifts every category score by up to ±0.15, as in the paper's 1,000 trials.
