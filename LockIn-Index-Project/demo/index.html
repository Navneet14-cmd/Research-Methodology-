Lock-In Index

Soni, Pant, Toshif

Static analysis of Infrastructure-as-Code

Measuring cloud vendor lock-in from Terraform code

The analyzer reads Terraform configurations, identifies every cloud resource they declare, and scores each resource on four lock-in dimensions. The resource scores are averaged into a single Lock-In Index (LII) from 0 to 100, which we use to answer four research questions.

Scoring formula
LII(r) = 0.35A + 0.25D + 0.25E + 0.15X
A
API proprietariness
D
Data / state lock
E
Equivalence gap
X
Egress exposure

A configuration's LII is the mean of its resource scores, scaled to 0–100.

Pipeline

From public repositories to a reproducible score.

  1. 01CollectPublic GitHub repositories, cloned at fixed commits
  2. 02Find rootsDirectories that are deployed directly
  3. 03ExtractEvery resource "type", following local modules
  4. 04Classify21 service categories assigned by pattern rules
  5. 05ScoreWeighted rubric across four dimensions
  6. 06AnalyseAverages, statistical tests, sensitivity, figures

What-if rubric

The rubric weights reflect our judgment. Adjust them and every score in the dataset is recalculated. If the conclusions still hold, they do not depend on our exact choices. This is RQ4, done interactively.

Dimension weights

Weights are normalised to sum to 1. “Random rubric” also shifts every category score by up to ±0.15, as in the paper's 1,000 trials.
